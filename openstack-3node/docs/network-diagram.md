## データフロー例

### 1. VMインスタンス作成時のフロー

```bash
1. ユーザー → Controller (eth1:管理NW)
   - openstack server create コマンド実行

2. Controller → Database (内部)
   - スケジューリング情報を取得

3. Controller → RabbitMQ → Compute (eth1:管理NW)
   - VM作成指示を送信

4. Compute → Controller (eth2:オーバーレイNW)
   - Glanceからイメージをダウンロード

5. Compute (内部)
   - KVMでVMを起動
```

### 2. VM間通信のフロー（同一テナント内）

```bash
1. VM1 (Compute1) → br-tun (VXLAN)

2. br-tun → eth2 (オーバーレイNW) → Network Node
   - VXLANトンネル経由

3. Network Node → eth2 → Compute1 (または他のCompute)
   - VXLANトンネル経由

4. Compute → VM2
```

### 3. VM → インターネット通信のフロー

```bash
1. VM (Compute1) → br-int → br-tun

2. br-tun → eth2 (VXLAN) → Network Node eth2

3. Network Node:
   - L3 Agent がルーティング
   - NAT実行

4. Network Node eth3 (外部NW) → インターネット
```

### 4. Floating IPによる外部アクセス

```bash
1. インターネット → Network Node eth3 (外部NW)

2. Network Node:
   - L3 Agent がFloating IP → 固定IPに変換

3. Network Node eth2 (VXLAN) → Compute eth2

4. Compute → VM
```

## ネットワークタイプ

### プロバイダーネットワーク（External）

- **タイプ**: FLAT
- **物理ネットワーク**: physnet1
- **対応インターフェース**: eth3 (Controller, Network)
- **用途**: Floating IP、外部接続

### テナントネットワーク（Private）

- **タイプ**: VXLAN
- **VNI範囲**: 1-16777215
- **対応インターフェース**: eth2 (全ノード)
- **用途**: VM間の分離された通信

## Open vSwitchブリッジ構成

### Network Node

```bash
br-ex (外部ブリッジ)
├─ eth3 (物理NIC)
└─ qg-xxxxx (ルーターの外部ポート)

br-int (統合ブリッジ)
├─ qr-xxxxx (ルーターの内部ポート)
└─ tap-xxxxx (DHCPポート等)

br-tun (トンネルブリッジ)
├─ eth2 (VXLAN用物理NIC)
└─ vxlan-xxxxx (VXLANトンネルポート)
```

### Compute Node

```bash
br-int (統合ブリッジ)
└─ qvo-xxxxx (VMの仮想NIC)

br-tun (トンネルブリッジ)
├─ eth2 (VXLAN用物理NIC)
└─ vxlan-xxxxx (VXLANトンネルポート)
```
